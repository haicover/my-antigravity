# 🚀 Antigravity Optimization (Tối ưu hóa Antigravity) — Master Guide 2026

Chào mừng bạn đến với trung tâm điều khiển lõi. Khác với các công cụ AI thông thường, **Antigravity** là một Agentic AI OS — nó có khả năng can thiệp trực tiếp vào File System và Execution Layer. Tài liệu này giúp bạn tinh chỉnh hệ thống để đạt hiệu suất 300% và giảm lỗi treo Terminal.

> **Triết lý cốt lõi:** Một hệ thống không độ trễ (Zero-latency) và một ngữ cảnh rõ ràng (Clear Context) là chìa khóa để AI Code nhanh hơn con người.

## 🎙️ Mentor Section (Góc Nhìn Chuyên Gia)

### 🇺🇸 English Perspective
Optimization in Antigravity isn't just about speed; it's about **Reliability**. Most bottlenecks occur when the Agent hits a system-level wall (like a locked file or a slow terminal). By isolating the Agent from unnecessary shell overhead and providing a rigid "Planning Mode", you transform the AI from a simple "Chatbot" into an "Autonomous Engineer". The goal is to minimize human intervention during the "Execute" phase.

### 🇻🇳 Góc Nhìn Tiếng Việt
Tối ưu hóa Antigravity nằm ở hai chữ: **"Hành Lang"**. Bạn cần xây dựng một hành lang kỹ thuật mượt mà (không lag terminal) và một hành lang logic chặt chẽ (Planning Mode). Khi Agent có một kế hoạch đã được duyệt và một đường truyền dữ liệu không bị Windows Defender cản trở, nó sẽ code nhanh gấp 10 lần so với việc bạn phải copy-paste từng đoạn code. Đừng làm thay Agent, hãy tối ưu môi trường để Agent làm cho bạn.

## ⚡ Elite Optimization Checklist (Quick Fixes)

1.  **Terminal Stability**: Tắt `windowsEnableConpty` trong Settings JSON.
2.  **Anti-lag**: Loại trừ thư mục dự án và `antigravity.exe` khỏi Windows Defender.
3.  **Command Flow**: Luôn ưu tiên `multi_replace_file_content` thay vì ghi đè toàn bộ file để tiết kiệm token và thời gian.
4.  **Context**: Sử dụng file `GEMINI.md` ở root dự án để định hướng hành vi của Agent.

## 🛠️ Cách Tôi Giúp Bạn

1.  **System Audit**: Kiểm tra file config Antigravity của bạn và đề xuất các thay đổi để chạy mượt hơn.
2.  **Workflow Design**: Thiết kế các file `task.md` mẫu cho các task phức tạp.
3.  **Rule Tuning**: Viết nội dung cho file `.gemini` để tôi có thể tự debug lỗi theo đúng ý đồ của bạn.
