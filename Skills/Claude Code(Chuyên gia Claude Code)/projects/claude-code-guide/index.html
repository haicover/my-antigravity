Phase 1

Enter the Vibe Coding Era

Before diving into Claude Code, understand the philosophy behind it. Vibe coding is about collaborating with AI at the speed of thought — describing intent and letting the agent handle implementation.

🎯
What is Vibe Coding?
The new development paradigm
▾
  • A development approach where you describe what you want in natural language, and the AI agent writes, debugs, and refactors code autonomously
  • Coined by Andrej Karpathy — "you fully give in to the vibes, embrace exponentials, and forget that the code even exists"
  • Shifts the developer role from writing code to directing outcomes
  • Requires strong communication, architecture thinking, and prompt engineering skills
🤖
What is a Coding Agent?
AI that writes & executes code
▾
  • An AI system that can read files, write code, run terminal commands, browse the web, and iterate on problems autonomously
  • Goes beyond autocomplete — it reasons, plans, and executes multi-step tasks
  • Claude Code is Anthropic's flagship coding agent, operating directly in your terminal
  • Available as CLI, desktop app, editor extensions (VS Code, JetBrains), and mobile channels
🔄
What is the Agentic Loop?
How AI agents think & act
▾
  • Observe → Read your codebase, files, errors, and context
  • Think → Reason about what needs to happen (chain-of-thought)
  • Act → Execute tools — edit files, run commands, search the web
  • Iterate → Check results, fix errors, refine until the task is complete
  • This loop runs continuously, making the agent feel autonomous and proactive
⚙️
Setting up Claude
Subscription vs API usage
▾
  • Subscription (Pro/Max): Fixed monthly cost. Claude Pro ($20/mo) or Max ($100/mo with 5× more usage). Best for individual developers
  • API Usage: Pay-per-token pricing. Best for teams, CI/CD pipelines, and programmatic access. Set up via ANTHROPIC_API_KEY
  • Install via npm install -g @anthropic-ai/claude-code
  • Authenticate by running claude and following the login flow
  • Available on: CLI, Desktop App, VS Code, JetBrains IDEs, Mobile

Phase 2

Core Concepts & Differences

Claude Code has a unique architecture built around context, modes, tools, and extensibility. Understanding these distinctions is essential.

📋
CLAUDE.md
Your project's memory file
▾
  • A markdown file Claude reads automatically at session start to understand your project
  • Contains project conventions, architecture decisions, coding standards, and commands
  • Think of it as a persistent system prompt for your codebase
  • Can be placed in repo root, subdirectories, or ~/.claude/CLAUDE.md globally
🧩
Skills
Reusable capability modules
▾
  • Focused instruction sets (SKILL.md files) that teach Claude specific capabilities
  • Unlike CLAUDE.md, skills are invoked on-demand rather than always loaded
  • Examples: "Deploy to AWS", "Write Jest tests", "Migrate database schema"
  • Composable — skills can reference other skills for complex workflows
🧠
Context
What the agent knows & sees
▾
  • Claude has a context window — everything in the conversation uses tokens
  • Files read, terminal output, search results all consume context
  • Managing context is the #1 skill for efficient Claude Code usage
  • Use /compact to summarize context, /clear to reset it
🔀
Modes
Plan, Act, or both
▾
  • Normal mode — Claude reads, writes, and executes freely
  • Plan mode (/plan) — Claude only plans, no code changes until you approve
  • Plan mode is essential for complex tasks — review before execution
  • Toggle between modes dynamically during a session
🛠️
Models, Tools & MCP
The engine and its extensions
▾
  • Models: Opus (deep reasoning), Sonnet (balanced), Haiku (fast & cheap)
  • Tools: Built-in capabilities — file editing, terminal, search, browser
  • MCP (Model Context Protocol): Standard for connecting external tools — databases, APIs, services
  • Plugins: Community and official extensions (e.g., Code Intelligence)
Flagship
Opus
Deep reasoning, complex architecture. Best for planning & hard bugs.
Balanced
Sonnet
Fast & capable. Default choice for most coding tasks.
Speed
Haiku
Ultra-fast, lightweight. Perfect for quick questions & simple edits.
🪝
Hooks & Subagents
Automation & delegation
▾
  • Hooks: Event-driven scripts that run before/after Claude actions (PreToolUse, PostToolUse, etc.)
  • Subagents: Spawn isolated Claude instances for parallel tasks
  • Hooks let you enforce guardrails — e.g., auto-lint after every file save
  • Subagents let you scale — e.g., one agent reviews code while another writes tests

Claude Workflow

Develop systematic workflows for using Claude Code effectively across different task types — from quick fixes to full-feature development.

Phase 4

Best Practices & Session Management

🔐
Permission Modes
Control what Claude can do
▾
  • Ask mode: Claude asks permission before every tool use (safest)
  • Auto-allow mode: Pre-approve safe operations like file reads
  • YOLO mode: Claude runs everything without asking (use with caution!)
  • Configure per-project via /permissions or in .claude/settings.json
  • Best practice: Use ask mode for unfamiliar codebases, auto-allow for trusted projects
📝
Plan Mode
Think before acting
▾
  • Activate with /plan — Claude researches and creates an implementation plan
  • Review the plan, ask questions, iterate on the approach
  • Exit plan mode and Claude executes the approved plan
  • Essential for: major refactors, new features, architectural changes
  • Skip for: quick bug fixes, formatting, simple one-liner tasks
📂
Manage Sessions
Resume & rewind conversations
▾
  • Resume: claude -r picks up where you left off, with full context
  • Rewind: /rewind rolls back to a previous point — undo mistakes
  • Sessions are persisted locally — you can resume days later
  • Use claude -c <id> to resume a specific older session by its ID
  • Tip: Start new sessions for distinct tasks to keep context clean
✅
Usage Best Practices
Work smarter, not harder
▾
  • Be specific: "Add error handling to the login function in auth.ts" beats "fix the login"
  • Provide context: Use @ file references to point Claude to relevant code
  • Iterate in small steps: Break large tasks into focused subtasks
  • Review diffs: Always review changes before accepting them
  • Use git: Commit before asking Claude to make major changes — easy rollback
  • Leverage tests: Ask Claude to write tests first, then implement — TDD workflow

Phase 5

Deep Customization & Agentic Patterns

📄
Mastering CLAUDE.md
Structure, locations, best practices
▾
  • How to Structure: Start with project overview, then conventions, common commands, gotchas
  • Use headers for sections: # Overview, # Architecture, # Commands, # Conventions
  • Locations (priority order): ~/.claude/CLAUDE.md (global) → repo root → subdirectories
  • Keep it concise — every token in CLAUDE.md costs context window space
  • Include examples of desired output format to train Claude's responses
🎓
Creating Skills
Build reusable instruction packs
▾
  • Create a SKILL.md file in any directory under your project
  • Skills are loaded on-demand — Claude discovers them when relevant
  • Best practices: One skill per domain, include examples, define clear boundaries
  • Compose skills by referencing others: "Use the deployment skill to push this to staging"
  • Store shared skills in ~/.claude/skills/ for cross-project reuse
🧬
Subagents
Spawn parallel Claude instances
▾
  • Subagents are isolated Claude instances spawned for specific subtasks
  • Run in their own context — don't pollute the parent's context window
  • Use for: parallel code reviews, test generation, documentation, research
  • Configure via /agents or .claude/agents.json
  • Each subagent can have its own model, tools, and permission settings
🪝
Hooks Deep Dive
Events, types, inputs & outputs
▾
  • Hook Events: SessionStart, SessionEnd, PreToolUse, PostToolUse, UserPromptSubmit, Stop
  • Hook Types: Shell commands, scripts, validation checks
  • Matchers: Filter hooks to specific tools (e.g., only run on write_file)
  • Inputs: Hooks receive the tool name, parameters, and session context
  • Outputs: Hooks can modify, block, or augment tool behavior
  • Example: Auto-run eslint --fix after every file write
📊
Managing Context
The most critical optimization skill
▾
  • Understand pricing: Every token in/out costs money. Opus is ~15× more expensive than Haiku
  • Use /compact and /clear: Compact summarizes; clear resets. Use compact first, clear if needed
  • Be mindful of extensions: MCP servers, plugins, and large file reads consume context fast
  • Use subagents and hooks: Offload subtasks to subagents to preserve parent context
  • Thinking modes & effort: Adjust reasoning depth — sometimes you don't need full chain-of-thought
  • Prompt caching: Anthropic caches repeated prompt prefixes — keep CLAUDE.md stable for savings
🔌
Connecting Tools with MCP
Extend Claude's capabilities
▾
  • MCP (Model Context Protocol): Open standard for connecting AI to external tools
  • Connect to databases, APIs, cloud services, Postman, GitHub, Slack, etc.
  • Configure MCP servers via /mcp or .claude/mcp.json
  • Skills for MCP: Create SKILL.md files that teach Claude how to use specific MCP servers
  • Channels: Bidirectional communication pathways for real-time data flow
Phase 06

Scaling & Production

Take Claude Code beyond individual use. Run headless pipelines, coordinate agent teams, customize output, and maintain security at scale.

6
Phase 6

Enterprise-Grade AI Development

🎛️
Model Configuration
Opusplan & model routing
▾
  • Opusplan: Use Opus for planning, Sonnet for execution — best of both worlds
  • Route tasks by complexity: Haiku for quick lookups, Sonnet for coding, Opus for architecture
  • Configure per-project model preferences in .claude/settings.json
  • Adjust thinking effort levels to optimize cost vs. quality tradeoff
📡
Headless Mode
CI/CD & automated pipelines
▾
  • Run Claude Code without interactive input — perfect for CI/CD pipelines
  • Use claude -p "task" --output json for machine-parseable output
  • Integrate into GitHub Actions, GitLab CI, or any automation workflow
  • Auto-review PRs, generate changelogs, run security audits — all unattended
🌿
Git Worktrees
Parallel branch development
▾
  • Use git worktrees to run multiple Claude instances on different branches simultaneously
  • Each worktree has its own working directory — no conflicts
  • Pattern: Main branch for features, worktree for bug fixes, another for experiments
  • Speeds up multi-task workflows dramatically
👥
Agent Teams
Orchestrated multi-agent workflows
▾
  • Coordinate multiple Claude instances working on the same project
  • Architect agent → assigns tasks. Worker agents → implement. Reviewer agent → validates
  • Combine with git worktrees for truly parallel development
  • Define team configurations in .claude/agents.json
🎨
Output Styles & Plugins
Customize Claude's behavior
▾
  • Output Styles: Control verbosity, formatting, and response structure
  • Customize status line: Show token count, cost, model, and custom info in the terminal
  • Scheduling Jobs: Cron-like scheduling for recurring Claude tasks
  • Code Intelligence plugin: Enhanced code navigation and understanding
🛡️
Security Best Practices
Keep your code & data safe
▾
  • Never expose API keys, secrets, or credentials in prompts or CLAUDE.md
  • Use environment variables and .env files (add to .gitignore)
  • Review all Claude-generated code for security vulnerabilities before merging
  • Use permission modes to restrict dangerous operations (file deletion, network access)
  • Implement hooks for security scanning — auto-run gitleaks or trivy on changes
  • Be cautious with MCP servers — only connect trusted, verified services
